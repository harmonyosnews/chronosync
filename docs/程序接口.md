# ChronoSync 程序接口

| 项目 | 内容 |
| --- | --- |
| 接口版本 | 1.4.0 |
| 传输 | HTTP/1.1，JSON（除首页、favicon、日志下载） |
| 认证 | 可选 HTTP Basic，作用于所有路由 |
| 默认地址 | `http://0.0.0.0:8686` |
| 请求体上限 | 512 KiB |
| 契约状态 | 1.4.0 稳定；1.3.0 保持兼容；无 OpenAPI 文件，本页为唯一契约 |

示例统一使用 RFC 5737 文档地址和占位密码，不得替换为真实凭据。

## 1. CLI

```text
chronosync [OPTIONS]
```

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--bind <ADDR>` | `0.0.0.0` | 监听地址；`127.0.0.1` 仅本机 |
| `--port <PORT>` | `8686` | 端口 1–65535 |
| `--ntp-servers <LIST>` | 阿里云/Cloudflare/pool 四个源 | 逗号分隔，自动去重 |
| `--auth <user:pass>` | 无 | Basic 认证；也可用 `CHRONOSYNC_AUTH` |
| `--log-dir <DIR>` | `./logs` | 任务日志目录 |
| `--allow-system-clock` | 关闭 | 所有 NTP 失败时允许降级本机时钟；危险 |
| `--open` | 关闭 | 启动后打开浏览器 |
| `--auto-port` | 关闭 | 绑定失败时尝试后续 10 个端口 |
| `--version` | | 版本 |
| `--help` | | 帮助 |

退出码：

| 码 | 含义 |
| --- | --- |
| 0 | 正常退出/help/version |
| 1 | 端口耗尽、服务异常 |
| 2 | 参数错误（如 `--auth` 无冒号、NTP 源为空、Clap 解析失败） |

启动时如果端口被占用，会先探测 `/api/health`；确认是 ChronoSync 则打印已有实例地址并退出，不重复启动。`--auto-port` 对 `AddrInUse`、权限拒绝 10013 等所有绑定错误都继续尝试后继端口。

## 2. HTTP 通用规则

### 2.1 Base URL

```text
http://<控制机>:<端口>
```

### 2.2 认证

启用 `--auth user:pass` 后，所有请求（包括 `/api/health` 和首页）都需要：

```http
Authorization: Basic <base64(user:pass)>
```

未通过返回 `401`，并带：

```http
WWW-Authenticate: Basic realm="ChronoSync", charset="UTF-8"
```

> Basic 认证不是加密。默认 HTTP 明文；只在可信内网使用，或放在 TLS 反向代理之后。

### 2.3 请求/响应

- JSON 请求使用 `Content-Type: application/json`。
- 成功响应为 JSON，首页为 HTML，日志下载为 `text/plain`。
- 错误统一为：

```json
{"error":"人类可读的错误","run_id":null}
```

`run_id` 当前保留为 `null`；异步任务错误通过 `/api/state` 查看。

### 2.4 状态码

| 码 | 场景 |
| --- | --- |
| 200 | 成功 |
| 400 | 请求体/设备/扫描范围校验失败 |
| 401 | 认证失败 |
| 409 | 已有校时/扫描任务、集群设置冲突，或运行中刷新参考 |
| 500 | 运行设置持久化失败 |
| 501 | 当前平台不支持 WebUI 重启 |
| 502 | NTP 刷新失败 |

### 2.5 安全响应头

所有响应附加：

```text
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline';
  script-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self';
  frame-ancestors 'none'; base-uri 'none'
```

## 3. 端点总览

| 方法 | 路径 | 作用 | 同步/异步 |
| --- | --- | --- | --- |
| GET | `/` | 内嵌 WebUI | 同步 |
| GET | `/favicon.ico` | 204 | 同步 |
| GET | `/api/health` | 健康/版本/构建信息 | 同步 |
| GET | `/api/state?since=<id>` | 状态、设备、增量日志 | 同步 |
| POST | `/api/reference/refresh` | 重新查询 NTP | 同步 |
| POST | `/api/sync` | 启动远程校时/检测 | 异步任务 |
| POST | `/api/local-sync` | 启动本机校时/检测 | 异步任务 |
| POST | `/api/scan` | 扫描局域网 | 同步（等待扫描完成） |
| GET | `/api/logs/download` | 下载当前进程日志 | 同步 |

## 4. 数据类型

### 4.1 MachineInput

```json
{
  "id": "node-1",
  "name": "test-node",
  "host": "192.0.2.10",
  "port": 22,
  "user": "root",
  "password": "REPLACE_ME"
}
```

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `id` | string/null | 否 | 1–80 字符，仅 ASCII 字母数字 `-` `_`；重复报错；省略则生成 `m-N` |
| `name` | string/null | 否 | 去除控制字符，最多 48 字符；空则用 host |
| `host` | string | 是 | 去空白；最多 253 字符；不允许空白/控制字符/`/`/`\`/`@`；可去掉 `[]` 的 IPv6 |
| `port` | number/null | 否 | 默认 22；0 报错；u16 |
| `user` | string | 是 | 非空，最多 128 字符，无空白/控制字符 |
| `password` | string | 是 | 非空，最多 1024 字节；不写日志/响应 |

整行 `host`、`user`、`password` 都为空会被跳过。单次最多 64 台；同一 `host:port` 或同一 `id` 重复均返回 400。

### 4.2 SyncOptions

```json
{"sync_hwclock": true, "sync_timezone": false, "dry_run": true}
```

三个字段默认 `false`。`dry_run=true` 只读；`sync_hwclock` 只影响写入模式；`sync_timezone` 尝试设为 `Asia/Shanghai`。

### 4.3 ReferenceView

```json
{
  "source": "ntp.aliyun.com",
  "rtt_ms": 29.4,
  "samples": 3,
  "verified": true,
  "age_ms": 1200,
  "epoch_ms": 1793789248123,
  "beijing": "2026-11-04 18:47:28",
  "utc": "2026-11-04 10:47:28",
  "created_at": "2026-11-04 18:47:27"
}
```

`verified=false` 表示降级到本机系统时钟；`age_ms` 基于单调时钟，不受控制机墙钟跳变影响。

### 4.4 MachineState

```json
{
  "id": "node-1",
  "name": "test-node",
  "host": "192.0.2.10",
  "port": 22,
  "status": "checked",
  "message": "检测完成 · 慢 120 毫秒",
  "run_id": 1,
  "hostname": "test-node",
  "timezone": "Asia/Shanghai",
  "remote_local": "2026-11-04 18:47:28 CST",
  "before_drift_ms": -120,
  "after_drift_ms": null,
  "after_local": null,
  "elapsed_ms": 42,
  "hwclock": null,
  "timezone_action": null,
  "warnings": []
}
```

状态：`pending`、`connecting`、`checking`、`setting`、`success`、`checked`、`error`。

`before_drift_ms` 是设备时间减标准时间（正数=设备快）；`after_drift_ms` 是写入后实测时间减目标时间，仅在成功写入或写入后校验失败时出现。设备清单“偏差”列据此显示 `+7 ms` / `-3 ms`。

### 4.5 LogEntry

```json
{"id": 12, "ts": "2026-11-04 18:47:28", "level": "success",
 "host": "test-node (192.0.2.10)", "message": "检测完成（未修改时间）· 慢 120 毫秒",
 "run_id": 1}
```

`level`：`system`、`info`、`success`、`warn`、`error`。消息已去 ANSI/控制字符并截断。

### 4.6 RunView

```json
{"id":1,"kind":"remote","status":"completed","total":2,"done":2,
 "success":2,"failed":0,"dry_run":true,
 "started_at":"2026-11-04 18:47:27","finished_at":"2026-11-04 18:47:29",
 "duration_ms":2000}
```

`kind`：`remote` / `local`；`status`：`running` / `completed` / `failed`。

### 4.7 ScanResult

```json
{
  "ranges": ["192.0.2.0/24"],
  "scanned": 254,
  "active_count": 2,
  "ssh_count": 1,
  "include_non_ssh": true,
  "duration_ms": 820,
  "hosts": [
    {"ip":"192.0.2.10","hostname":"test-node","ssh_open":true},
    {"ip":"192.0.2.11","hostname":null,"ssh_open":false}
  ]
}
```

## 5. 端点详情

### 5.1 GET `/api/health`

无需请求体；认证启用时仍需认证。

```json
{
  "ok": true,
  "instance_id": "12345-1793789248123456789",
  "version": "1.4.0",
  "build": {"target":"x86_64-unknown-linux-musl","variant":"x86-64-v1","time":"20261106-150000"},
  "running": false,
  "sync_ready": true,
  "now_beijing": "2026-11-04 18:47:28"
}
```

用途：启动探活、重复实例检测、容器/监控健康检查。`instance_id` 在每次进程启动（含 WebUI 原地重启）时变化，前端用它确认新实例已经就绪。

### 5.2 GET `/api/state`

查询参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `since` | 0 | 只返回 `id > since` 的日志，用于增量轮询 |

响应：

```json
{
  "now_epoch_ms": 1793789248123,
  "now_beijing": "2026-11-04 18:47:28",
  "now_utc": "2026-11-04 10:47:28",
  "reference": { "...": "ReferenceView 或 null" },
  "running": false,
  "scanning": false,
  "sync_ready": true,
  "restart_supported": true,
  "run": { "...": "RunView 或 null" },
  "machines": [],
  "logs": [],
  "log_total": 0,
  "local": {"hostname":"control","privileged":false,"timezone":"Asia/Shanghai"}
}
```

`machines` 按 host、port、id 排序；`log_total` 是当前进程累计日志数。日志最多保留 8000 条，旧日志被裁剪后 `since` 仍可用于增量。`restart_supported=false` 表示当前平台不支持 WebUI 内重启（当前为 Windows）。

### 5.3 POST `/api/reference/refresh`

请求体：无（空 body）。

成功：`200` + `ReferenceView`。运行中：`409`。NTP 失败：`502`，并记录错误；若当前没有参考，会设置未验证的本机时钟参考，但 `sync_ready` 仍为 false（除非 `allow_system_clock`）。

### 5.4 POST `/api/sync`

```json
{
  "machines": [{"id":"node-1","name":"test-node","host":"192.0.2.10","port":22,"user":"root","password":"REPLACE_ME"}],
  "options": {"dry_run": true, "sync_hwclock": false, "sync_timezone": false}
}
```

成功：`200 {"started":true,"run_id":1}`。任务异步执行，用 `/api/state` 轮询。校验失败：`400`；已有任务：`409`。

重要：这是写入接口。生产使用前必须先用 `dry_run=true`；本文档不提供“跳过确认”的参数。

### 5.5 POST `/api/local-sync`

```json
{"options":{"dry_run":true,"sync_hwclock":false,"sync_timezone":false}}
```

成功/错误同上；`run.kind="local"`，`total=1`。写入需要控制机 root/管理员。

### 5.6 POST `/api/scan`

```json
{"cidrs":["192.0.2.0/24"],"include_non_ssh":true}
```

`cidrs` 为空数组表示自动探测；`include_non_ssh` 默认 true。成功：`200` + `ScanResult`。范围错误：`400`；已有任务/扫描：`409`。

限制：

- 每个自定义网段 `/22` 到 `/32`；最多 4 个网段/1024 个地址。
- 自动模式每接口取 /24 上限，跳过回环/链路本地/虚拟接口。
- 只探测 TCP 22 + 本机邻居表 + 反向 DNS，不登录目标。

### 5.7 GET `/api/logs/download`

返回 `text/plain; charset=utf-8`，附件文件名 `chronosync-logs-YYYYMMDD-HHMMSS.log`，内容是当前进程全部日志（含导出时间、时间源、主机、偏差、警告/错误）。不包含 SSH 密码。

## 6. 远程命令协议（内部）

以下不是稳定 API，仅用于排障。远程脚本通过 `__CS_*` 标记返回结果：

| 标记 | 含义 |
| --- | --- |
| `__CS_HOST__` | 主机名 |
| `__CS_EPOCH__` | 远程 UTC epoch |
| `__CS_LOCAL__` | 远程本地时间 |
| `__CS_TZ__` / `__CS_TZNAME__` | 时区路径/名称 |
| `__CS_SET_RC__0/1` | 时间写入成功/失败 |
| `__CS_TZ_ACTION__` | `ok` / `already` / `failed` / `missing-data` / `skipped` |
| `__CS_HWC__` | `ok` / `ok-directisa` / `no-rtc` / `missing-binary` / `failed` / `skipped` |
| `__CS_NOW_EPOCH__` / `__CS_NOW_LOCAL__` | 写入后校验时间 |

预检和写入命令依赖 POSIX sh、`date`；`hwclock`/`timedatectl`/tzdata 可选。不要在外部脚本中依赖标记格式。

## 7. cURL 示例

```bash
BASE=http://127.0.0.1:8686
curl -s "$BASE/api/health"
curl -s "$BASE/api/state?since=0"
curl -s -X POST -H 'Content-Type: application/json' \
  --data '{"options":{"dry_run":true}}' "$BASE/api/local-sync"
curl -s -X POST -H 'Content-Type: application/json' \
  --data '{"machines":[{"name":"test","host":"192.0.2.10","port":22,"user":"root","password":"REPLACE_ME"}],"options":{"dry_run":true}}' \
  "$BASE/api/sync"
```

启用认证时加：

```bash
curl -u admin:'REPLACE_ME' ...
```

不要把真实密码写进 shell 历史；可用临时环境变量和 `curl -u "$AUTH"`，测试后清理。

## 8. 兼容性与限制

- 无 API 版本前缀；升级前看 CHANGELOG。
- 无 WebSocket/SSE；UI 使用轮询。
- 无持久化设备库；设备状态只在进程内。
- `run_id` 在错误体中保留为 null，异步错误看状态。
- 主机密钥当前不固定；HTTP 无 TLS；两者都是已知风险，见 [审计报告](审计报告.md)。

## 9. 集群扩展（1.3.0/1.4.0）

> 以下接口从 1.1.0 起提供，1.2.0/1.3.0 保持兼容。

### 9.1 新增 CLI

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--cluster-mode <off\|server\|client\|auto>` | `off` | 集群角色；生产默认手动 server |
| `--cluster-id <ID>` | `chronosync` | 集群标识 |
| `--node-id <ID>` | 自动生成 | 持久节点标识 |
| `--cluster-secret-file <PATH>` | 无 | 共享密钥文件；非 off 必填 |
| `--cluster-bind <ADDR>` | `0.0.0.0` | 集群 UDP 绑定地址 |
| `--discovery-port <PORT>` | `18686` | 发现端口 |
| `--time-port <PORT>` | `18687` | 时间服务端口 |
| `--cluster-ntp123` | 关闭 | 可选标准 NTPv4 UDP 服务 |
| `--cluster-ntp123-port <PORT>` | `123` | 标准 NTPv4 端口 |
| `--server-eligible <true\|false>` | `true` | 是否可被选为 server |
| `--auto-apply` | 关闭 | client 自动写本机时间 |
| `--max-offset-ms <MS>` | `100` | 自动写入阈值 |
| `--max-step-ms <MS>` | `5000` | 单次最大跳变 |
| `--allow-large-step` | 关闭 | 允许超过最大跳变 |
| `--sync-interval <SEC>` | `60` | client 同步间隔 |
| `--cluster-state-dir <DIR>` | `./cluster-state` | node-id 持久目录 |
| `--cluster-seed <ADDR>` | 无 | 额外 seed（ip:port） |

### 9.2 `GET /api/cluster/state`

未启用集群时返回 `null`；启用时返回：

```json
{
  "enabled": true,
  "mode": "auto",
  "role": "client",
  "term": 2,
  "node_id": "client-0001",
  "server_id": "server-0001",
  "server_addr": "192.0.2.10:18687",
  "peers": 1,
  "ntp_verified": true,
  "ntp123": true,
  "ntp123_port": 123,
  "ntp123_error": null,
  "manual_server": false,
  "auto_apply": false,
  "last_sync": {
    "offset_ms": 12,
    "rtt_ms": 3,
    "at": "2026-11-06 11:15:29",
    "applied": false,
    "message": "自动写入已关闭，仅检测"
  },
  "last_error": null
}
```

`/api/state` 也新增 `cluster` 字段，内容相同或 `null`。`mode` 是运行时生效模式（手动 Server 覆盖启动模式），`manual_server` 表示本机固定 Server 开关，`ntp123` 表示监听器当前是否真正绑定成功；绑定失败原因放在 `ntp123_error`。集群 UDP 消息不是公开 API；不要依赖内部字段。安全/自动写入语义见 [集群模式详细设计与排期](集群模式详细设计与排期.md)。

### 9.3 POST `/api/cluster/settings`

请求体至少包含一个字段：

```json
{"ntp123": true, "manual_server": false}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ntp123` | boolean/null | 热启停标准 NTPv4 监听器；绑定失败返回 409，设置不落盘 |
| `manual_server` | boolean/null | `true` 立即提升本机为 Server；`false` 取消固定并按启动模式回退 |

成功：`200` + 最新 `ClusterView`。无集群：`409`。校时/扫描中切换角色：`409`。至少一个字段缺失：`400`。设置写入日志目录 `runtime.json`（0600），重启后继续生效。

### 9.4 POST `/api/system/restart`

请求体：无。

成功：`202 {"ok":true,"message":"服务正在重启，页面将自动重新连接"}`。校时/扫描中或已有重启请求：`409`。Windows：`501`。

Linux/Unix 使用原地 `exec`，PID 保持不变；systemd/OpenRC/procd 仍跟踪同一主进程。音频播放或正在写入的设备会短暂中断，前端会等待新的 `instance_id` 后刷新页面。
