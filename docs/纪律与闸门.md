# 纪律与闸门

本文件是 ChronoSync **闸门定义的唯一权威来源**。项目书、实施方案、验收记录、AGENTS.md 只引用，不复制完整规则。

## 1. 适用范围

- 运行时/安装器/WebUI/依赖变更：必须走 G1–G13。
- 纯文档变更：至少走 G1、G4、G10、G11、G14；不重建二进制。
- 已发布版本：tag 和 Release 资产不可改写。运行时修复必须发新版本。
- 24 小时长稳测试已按项目决定取消，不列为闸门；不得在验收中写成“待跑”。

## 3. 执行顺序

```text
报告/范围 → 修复 → G1–G6 → G7 → G8 → G9 → G10–G11 → G12 → G13 → 冻结/发布
```

纯文档：

```text
G1 → G4 → G10 → G11 → G14 → 提交
```

G7–G9、G12 对文档变更不适用；在记录中写 `N/A (docs-only)`，不要写 PASS。

## 4. 证据要求

1. 记录命令、构建时间、版本、日期、执行人/自动化标识。
2. 真机证据必须脱敏：数量、状态、耗时、错误分类；不写密码/完整 IP 清单/主机名。
3. 失败必须保留：包括失败命令、错误分类、是否重试、最终结果。
4. 截图/日志可作为附件，但不得含凭据。
5. 发布证据以 tag、Release、`SHA256SUMS`、公开回读为准；本地文件不是唯一证据。
6. 未执行的测试写 `NOT RUN`/`CANCELED`，不能写 `PASS`。

## 5. 严重度与豁免

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 批量错误时间、凭据泄露、远程接管 | 阻断发布；立即修复/回滚 |
| P1 | 单机错误、认证绕过、包不可用 | 阻断发布；修复后全量复测 |
| P2 | 有限泄密/兼容性缺陷/重要债务 | 项目负责人书面豁免；登记 Issues |
| P3 | 文案/低风险债务/优化 | 可随下一版本；登记 Issues |

豁免必须包含：ID、原因、影响范围、补偿措施、到期版本、批准人。没有补偿措施的 P0/P1 不得豁免。

## 6. 角色

| 角色 | 职责 |
| --- | --- |
| 作者 | 实现、测试、更新文档、提供证据 |
| 评审人 | 代码/安全/兼容性审查，核对 G1–G6 |
| 发布经理 | 冻结、构建、G7–G13、资产回读 |
| 验收人 | 核对验收记录、签认 |
| 安全评审 | 风险接受/豁免，抽查 G10 |

作者不能独自批准自己的 P0/P1 豁免；发布经理不能修改已发布资产。

## 8. 违规处理

- 发现凭据/token 进入仓库：立即撤销 token/改密，清理历史，重跑 G10，评估是否发布。
- 发现已发布包错误：停止分发，发布勘误/新版本；不覆盖旧资产。
- 发现文档声称未执行的测试：按 P1 处理，修正文档并记录。
- 发现跳过闸门：补跑；无法补跑则在新版本重新验收。
