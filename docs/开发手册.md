## 1. 环境

- Rust 1.89+（1.0.2 使用 1.99.1 构建）。
- C 编译器（ring 加密后端）。
- Node.js（仅用于 WebUI JavaScript 语法检查）。
- Linux 目标发布需要 glibc ≥ 2.39；Windows 用 MinGW-w64；ARM64 用 aarch64 GNU 交叉工具链。
- 浏览器回归需要 Chromium/Playwright（非编译必需）。

完整工具链搭建、交叉编译和静态编译限制见 [编译环境与静态编译](程序编译环境的搭建与实施-静态编译.md)。

## 2. 仓库结构

```text
src/
  main.rs    CLI、端口、启动、重复实例探测、浏览器打开
  app.rs     API、状态机、运行编排、日志、校验、安全头
  ntp.rs     SNTP 查询、标准时间锚点、UTC/北京时间格式
  remote.rs  SSH 客户端、认证、远程命令、结果解析
  local.rs   本机时间/RTC/时区/权限
  scan.rs    网段规划、TCP 探测、邻居表、反向 DNS
web/index.html  单文件 WebUI（编译期嵌入）
build.rs        注入 target/variant/time
install.sh      安装/卸载/状态
packaging/      systemd 和 Windows 启动脚本模板
reports/        发布/构建/真机/闸门证据
docs/           项目文档
```

## 3. 模块约定

### 3.1 时间

- 内部统一使用 UTC epoch 毫秒（`i64`）；字段名以 `_ms` 结尾。
- 展示层用 `format_beijing` / `format_utc`；不要在业务逻辑里混用本地时间。
- 标准时间参考必须锚定 `Instant`，避免控制机墙钟被改后 UI 跳变。
- NTP offset 的符号是“服务器时间 − 本机时间”；标准时间 = 本机采样 + offset，已有回归测试。
- 秒级写入会把目标 epoch 四舍五入到整秒；校验偏差阈值要覆盖 SSH/RTC 延迟。

### 3.2 错误

- 模块边界返回 `Result<_, String>`；HTTP 层转成 `ApiError { error, run_id }`。
- 运行时不要用 `unwrap`/`expect` 处理外部输入；测试可以使用。
- 面向用户的错误要说明“发生了什么 + 下一步”，不要把密码、完整命令或内部堆栈写进日志。
- 可选步骤（RTC/时区）失败是警告，不是系统时间失败；不能混淆状态。

### 3.3 并发与状态

- `App.inner.activity` 互斥校时/扫描；`running`、`scanning` 是原子状态。
- 远程任务最多 8 并发；扫描 128 探测/32 DNS 并发。
- 设备状态机：`pending → connecting → checking → setting → success|error`；检测模式为 `checked`。
- 任务结束必须 `finalize_run`，未完成设备标记“任务中断，结果未知”。

### 3.4 日志

- 所有外部字符串先 `sanitize_text`（去 ANSI/控制字符、截断）。
- 日志上限 8000 条；任务日志落盘失败只警告。
- 日志不得包含密码、token、完整凭据；设备只显示名称/地址。
- 新增日志字段要同步日志下载渲染和测试。

### 3.5 WebUI

- 单文件 HTML/CSS/JS，无外部依赖；通过 `include_str!` 嵌入。
- 状态轮询 `/api/state?since=<lastLogId>`；不要新增高频轮询。
- 破坏性操作必须有确认弹窗；清除设备同时清理密码 localStorage。
- 密码默认不持久化；“记住密码”是显式 opt-in。
- 新增 DOM id 要同步 `cacheElements`；修改 CSP 要评估内联脚本。

## 4. 本地开发

```bash
cargo fmt
cargo clippy --all-targets -- -D warnings
cargo test
cargo run -- --bind 127.0.0.1 --port 8686 --log-dir ./logs
```

启动后访问 `http://127.0.0.1:8686/`。没有目标设备时可用“本机校时 + 仅检测”验证 UI/NTP/日志路径，不会修改时间。

### 4.1 测试分层

| 层级 | 内容 | 命令/位置 |
| --- | --- | --- |
| 单元 | NTP 解析/符号、时区、CIDR、邻居住析、输入校验、日志渲染 | `cargo test` |
| 静态 | fmt、clippy、JS 语法、install sh 语法 | 见闸门文档 |
| 浏览器 | 清除/记住密码/扫描/日志/无控制台错误 | Playwright/Chromium |
| 安装 | `--dry-run` 平台识别 | `./install.sh --dry-run --binary /bin/true --no-start` |
| 真机 | 只读 dry-run、平台启动 | 需授权环境，禁止写入生产时钟 |

### 4.2 调试

- `/api/health`：版本、构建 target/variant/time、`sync_ready`。
- `/api/state`：运行状态、设备偏差、日志增量。
- 控制台启动摘要：监听地址、权限、日志目录、NTP 来源。
- SSH 失败先手工 `ssh`；RTC 问题查 `/dev/rtc*` 和 `hwclock --show`。
- Windows 端口用 `netstat -ano` + `tasklist`，不要用 Linux 的 `kill`。

## 5. 修改流程

1. 在 Issue/任务中写清范围、风险和验收标准。
2. 修改代码 + 测试 + 文档；不把真实凭据/内网清单写入仓库。
3. 本地跑 G1–G6；涉及构建再跑 G7/G9；涉及行为跑 G8。
4. 更新 `CHANGELOG.md`；必要时更新 `docs/程序接口.md`、`使用手册.md`。
5. 提交前做敏感扫描；发布按 [纪律与闸门](纪律与闸门.md)。
6. 已发布 tag 不改写；运行时修改进入新版本。

## 6. 已知技术债与优化候选

这些不阻塞 1.0.2，记录在 [Issues 整理](Issues整理.md)：

- `ntp::system_epoch_ms` 与 `local::current_epoch_ms` 重复，可抽公共时间工具。
- `optional_step_label` 与 `optional_step_label_local` 近重复，可合并。
- `fail_target` 只是 `fail_target_with_drift` 的薄包装，可删除。
- `ip_from_neighbor_line` 仅测试使用，`add_neighbors` 有相似解析；可复用并去 `dead_code`。
- `beijing_datetime` / `format_utc` 的 DateTime 构造重复，可抽 helper。
- 主机密钥固定、CSRF/限流、常量时间认证比较属于安全增强，需新版本设计。

## 7. 扩展点

- **新发行版**：优先改远程 shell 命令探测/降级，不改 Rust 目标逻辑。
- **新平台**：在 `local.rs` 加 `cfg` 实现，在 `install.sh` 加平台检测和 service 模板。
- **新 API**：在 `app.rs` 定义请求/响应结构、校验、并发语义，并更新 `程序接口.md`。
- **认证**：当前 Basic；若要 token/SSO，先设计 CSRF、会话、TLS 和审计。
- **主机密钥**：增加 known_hosts/pinning 需要配置模型和失败策略，不能默认静默接受。
