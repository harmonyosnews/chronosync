- 控制机：Linux x86_64（WSL2），Rust 1.99.1，glibc 2.43。
- 构建：x86_64 GNU、aarch64 GNU 交叉、MinGW-w64。
- 目标：Debian/Arch/Gentoo/Buildroot/BusyBox 等真实设备；Windows 控制机；真实 ARMv8 主机。
- 网络：受控局域网；文档不记录真实地址。

## 5. 复现：浏览器回归

前置：Node.js + Playwright + Chromium；启动本机服务（不配置认证，便于测试）：

```bash
cargo run --release -- --bind 127.0.0.1 --port 18800 --log-dir /tmp/cs-ui
```

浏览器测试应覆盖：

1. 页脚版本 `ChronoSync v1.0.2`。
2. 日志视窗约 330 px（约 10 行）。
3. 空清单“清除设备”禁用；确认后行清空、设备/密码 localStorage 删除。
4. “记住 SSH 密码”默认关闭；关闭时刷新密码为空、用户名保留；开启后刷新恢复密码。
5. 扫描弹窗可打开/取消。
6. console error 和 pageerror 为 0。

> 浏览器脚本依赖 Playwright；仓库不附带该依赖，避免把测试框架打进运行时。CI/本地可按上述断言实现。

## 6. 复现：真机只读测试

### 6.1 安全前置

- 只在获得授权的测试机/维护窗口执行。
- 必须 `dry_run=true`，且 `sync_hwclock=false`、`sync_timezone=false`。
- 不在生产机群做写入测试。
- 凭据从环境变量/临时文件读取，测试后删除；禁止提交。

### 6.2 请求模板

```bash
BASE=http://127.0.0.1:8686
AUTH='admin:REPLACE_ME'          # 如启用认证
TARGET_HOST=192.0.2.10           # RFC 5737 文档地址，替换为授权测试地址
TARGET_USER=root
TARGET_PASS='REPLACE_ME'         # 不写入仓库/日志/截图

curl -s -u "$AUTH" -X POST "$BASE/api/sync" \
  -H 'Content-Type: application/json' \
  --data "{\"machines\":[{\"name\":\"lab-node\",\"host\":\"$TARGET_HOST\",\"port\":22,\"user\":\"$TARGET_USER\",\"password\":\"$TARGET_PASS\"}],\"options\":{\"dry_run\":true,\"sync_hwclock\":false,\"sync_timezone\":false}}"
```

轮询：

```bash
curl -s -u "$AUTH" "$BASE/api/state" | python3 -m json.tool
```

通过标准：目标 `status=checked`，有 `before_drift_ms`，没有写入；不可达/认证失败应明确分类。

### 6.3 批量结果（1.0.2 实际）

- 12 台目标：11 台 `checked` 并读取偏差；1 台 SSH 不可达。
- 总耗时 2585 ms；`dry_run=true`；未执行 `date -s`/`hwclock -w`/时区写入。
- Windows：1 台真实设备 `checked`；445 被占用时回退 446，健康 200。
- ARM64：真实 aarch64 启动，`version=1.0.2`，健康 200。

详细数量/时间见 [真机报告](../reports/REAL-DEVICE-TESTS-1.0.2.md)；不记录真实设备清单。

## 7. 复现：发布包校验

```bash
cd dist
sha256sum -c SHA256SUMS
for f in chronosync-1.0.2-linux-x86_64-v1-*.tar.gz; do
  tar -tzf "$f" | head
  d=$(mktemp -d); tar -xzf "$f" -C "$d"
  "$d"/*/chronosync --version
  rm -rf "$d"
done
```

Windows 包解压后运行 `chronosync.exe --version` 或 `start-chronosync.bat`；检查 `BUILD-INFO.txt` 的 target/variant/time。公开资产可用 Release 页下载。

## 8. 不能声称的结论

本轮没有做以下事情，文档不得把它们写成通过：

- 没有在生产设备执行时间写入（只读测试）。
- 没有完成 24 小时长稳测试（项目已取消该测试项）。
- 没有产出静态 musl 发布包（当前发布为动态 glibc；方案见编译文档）。
- 没有验证公网/不可信网络下的安全性（工具假设可信内网）。
- 没有固定 SSH 主机密钥（接受任意主机密钥是已知风险）。
