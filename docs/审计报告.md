## 2. 总结

- **科学性**：时间参考使用多源采样、中位数/离群过滤、RTT 选择、单调时钟锚点；offset 符号有单元测试。NTP 无认证、无置信区间，是协议层限制，已记录。
- **逻辑性**：NTP 失败默认锁定；预检失败不写入；写入后校验；可选 RTC/时区失败不否定系统时间；任务互斥和并发上限清晰。
- **鲁棒性**：SSH/命令超时、输出截断、输入长度/字符校验、CIDR/地址上限、端口回退、日志脱敏、Mutual exclusion。未发现运行时 `unwrap` 造成的可达 panic（测试代码除外）。
- **归一化**：UTC 内部、北京时间展示；`_ms`/`_s` 命名；设备状态、日志级别、包标签一致。文档已建立单一事实源。
- **冗余**：运行时代码有 4 处低风险重复/死代码；文档重复表已通过索引和权威链接收敛。已发布 1.0.2 不因去重而重建。

## 4. 科学性审计

### 4.1 时间参考

`probe()` 并行查询所有源，1.5s 超时；≥3 个样本时取中位数并剔除偏离 >0.5s 的源，再选最低 RTT；以 `Instant` 锚定标准时间。`parse_response` 计算：

```text
offset = ((t2 - t1) + (t3 - t4)) / 2
rtt    = (t4 - t1) - (t3 - t2)
standard = local_sample + offset
```

单元测试验证 offset 符号、NTP 时间戳往返、Kiss-o'-Death 拒绝。**优点**：不信任本机墙钟；失败锁定。**限制**：SNTP 无认证；0.5s 离群阈值是工程值，不是统计置信区间；源数量少时抗攻击能力有限；闰秒由系统/NTP 生态处理，本工具不单独处理。

### 4.2 量化与阈值

- 远程写入目标 = 当前标准时间 + 80ms，按整秒写入；校验偏差阈值 2500ms。
- 本机校验阈值 1500ms。
- 偏差展示按 ms/s/min/hour/day 分级。
- 这些阈值覆盖 SSH/RTC 延迟，但不是形式化证明；对高精度场景不适用。

## 5. 逻辑性审计

- NTP 失败：`acquire_reference_for_run` 先尝试新探测；仅当存在 5 分钟内已验证快照才继续；否则任务终止，所有目标标“未执行”。
- 预检失败/解析失败：不进入写入分支。
- 写入：先系统时间，后可选时区/RTC；后两者失败只警告。
- 校验：写入后重新读取；偏差过大或读不到均标失败。
- 并发：`activity` 互斥 + `running/scanning` 原子状态；最多 8 目标并发；扫描与校时互斥。
- 任务结束：`finalize_run` 将未完成设备标“任务中断”，避免 UI 永久 running。

未发现“失败被当成成功”的可达路径；可选步骤的警告与系统时间成功有明确区分。

## 6. 鲁棒性审计

| 方面 | 控制 | 残余风险 |
| --- | --- | --- |
| SSH 连接/认证/执行 | 10/12/25s 超时；输出 128K/32K 截断 | 极慢链路可能超时 |
| 输入 | host/user/password/id 长度与字符校验；最多 64 台 | 超长合法主机名边界 |
| 扫描 | /22 最小、4 网段/1024 地址、并发 128/32 | 跨路由静默主机发现不到 |
| 端口 | 重复实例探测；`--auto-port` 任意绑定错误回退 | 10 个后继都占用则失败 |
| 日志 | 去 ANSI/控制字符、8000 条上限、落盘失败不致命 | 敏感信息依赖调用方不传 |
| 状态 | Mutex poison 恢复；原子状态；RunGuard/ScanGuard Drop | 进程崩溃时状态丢失 |
| 平台 | Windows/Unix cfg；RTC/时区降级 | 本机 Windows RTC 跳过 |

运行时未发现可轻易触发 panic 的 `unwrap`；测试中的 `unwrap` 不影响生产。`lock()` 对 poison 做恢复，避免一次 panic 让所有 API 失败。

## 7. 归一化审计

- **时间**：内部 UTC epoch ms；展示北京时间/UTC；字段 `_ms`；NTP 秒与毫秒转换集中在 `ntp.rs`。
- **命名**：`sync_hwclock`、`sync_timezone`、`dry_run` 在 API/CLI/UI 一致；状态 `checked/success/error` 语义明确。
- **包**：版本-系统-架构-变体-时间戳；`BUILD-INFO` 与 `/api/health` 一致。
- **文档**：API/闸门/排期分别有唯一权威文档；其他文档链接，不复制长表。
- **待改进**：`current_epoch_ms` 与 `system_epoch_ms` 重复；`optional_step_label` 两份；`fail_target` 薄包装；`ip_from_neighbor_line` 死代码。属低风险债务，进入 Issues。

## 8. 安全审计

### 8.1 已控制

- 密码不写日志/响应；日志导出不含密码。
- 记住密码默认关闭；清除设备删除 localStorage。
- CSP、nosniff、DENY frame、no-referrer。
- 请求体 512KiB；设备数/密码长度/主机字符限制。
- 发布 token 不进入仓库/命令参数/资产；发布前敏感扫描。
- NTP 失败锁定，避免写入错误时间。

### 8.2 残余风险

- 主机密钥不固定 → 中间人。
- HTTP 明文/Basic → 嗅探。
- localStorage 明文密码 → 本机其他用户/恶意扩展。
- 无 CSRF/限流 → 恶意网页/内网滥用（有 Basic 时仍需凭据）。
- NTP 无认证 → 恶意时间源。
- root SSH → 凭据泄露即主机接管。

这些风险在 [可行性分析](可行性分析.md) 和 [项目书](项目书.md) 中列为使用前提；不是“已修复”。

## 10. 审计结论

**有条件通过**：

1. 1.0.2 可作为可信内网运维工具使用；不得直接暴露公网。
2. 生产部署必须启用访问控制/网络隔离，先只读检测。
3. 已接受的 4 项中等风险必须有操作层补偿；未补偿环境不得使用。
4. 代码债务和安全增强进入后续版本，不修改已发布 1.0.2。
5. 24h 长稳测试已取消，不作为通过条件；其缺失不再列为未完成项。
