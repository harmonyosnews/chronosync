## 1. 背景与问题

机群中同时存在 Debian、Arch、Gentoo、Buildroot、BusyBox 等系统。它们的时间可能因 RTC 缺失、NTP 配置错误、长期离线或虚拟化时钟漂移而不一致。逐个登录执行 `date`、`hwclock` 既慢又容易漏项；在目标机安装代理又会受固件、只读根文件系统、包管理器差异限制。

ChronoSync 选择“控制机集中操作”的路线：控制机从 NTP 取得可信标准时间，通过 SSH 在目标机执行最小命令。目标机不需要外网、不需要安装额外服务，也不改变目标机的 NTP 配置。

## 2. 项目目标

1. 用一台控制机批量校准多台 Linux 设备到北京时间。
2. 同时支持“仅检测”、单台、本机和批量操作。
3. 对不同发行版和嵌入式固件保持命令兼容。
4. 提供中文 WebUI，WebUI 编译进单文件二进制，减少部署文件。
5. 对 NTP 失败、RTC 缺失、SSH 认证差异、端口占用等常见故障给出明确、安全的行为。
6. 形成可复现的构建、测试、发布和审计证据链。

## 3. 非目标

- 不在目标机常驻代理，不替代 chrony/systemd-timesyncd。
- 不提供 NTP 服务器、NTS 或时间源认证。
- 不提供公网级身份认证、TLS 终止、集中审计平台。
- 不自动发现或保存真实机群清单到服务端。
- 不做持续定时校时；校时是人工触发的运维动作。
- 不保证在不可信网络中安全传输 SSH 密码；默认假设可信内网。

## 6. 成功标准

1. **功能**：NTP 参考、批量/单台/本机、仅检测、扫描、日志、清除设备、可选密码保留可用。
2. **安全**：NTP 不可达默认拒绝写入；日志不出现密码；默认不持久化密码。
3. **兼容**：至少通过 Debian/Arch/Gentoo/Buildroot/BusyBox 的真实只读检查；Windows 和 ARM64 能启动。
4. **质量**：`cargo fmt`、`clippy -D warnings`、单元测试、JS 语法、浏览器回归、安装 dry-run 全通过。
5. **可复现**：构建时间、target、CPU 变体可查询；包内 `BUILD-INFO.txt` 和 SHA256 可校验。
6. **发布**：tag/Release/资产可回读；文档中的版本、哈希和链接一致。

1.0.2 的实际结果见 [实施与验收记录](实施与验收记录.md)，不在本文件重复。

## 7. 约束与假设

- 目标机允许 root（或有权限用户）通过 SSH 密码或 keyboard-interactive 登录。
- 控制机能访问目标 SSH 端口和 UDP 123；目标机不必访问外网。
- 目标 `/bin/sh` 支持 POSIX 基本语法；`date` 必须存在。
- Linux 预编译包要求 glibc ≥ 2.39；旧系统需本地编译。
- 控制台默认明文 HTTP，只在可信内网使用。
- 目标机可能没有 RTC、timedatectl 或 tzdata，工具必须降级而不是整体失败。
- 24 小时长稳测试已按项目决定取消，不作为本项目交付或验收条件。

## 8. 风险与控制

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| 目标机 SSH 凭据泄露 | 高 | 不写日志/仓库；密码默认不持久化；发布前敏感扫描 |
| 控制台被局域网滥用 | 高 | `--auth`、可信内网、可绑定 127.0.0.1；文档明确无 TLS |
| NTP 源错误或不可达 | 高 | 多源中位数/离群过滤；失败锁定；快照仅 5 分钟 |
| 目标时钟被其他服务改写 | 中 | 写入后校验；偏差超阈值标失败 |
| RTC 缺失导致误判 | 中 | direct ISA 探测、无 RTC 跳过并提示 |
| Windows 端口占用 | 中 | 重复实例探测、任意绑定错误自动换端口 |
| 构建/发布不可复现 | 中 | 固定 target/变体/时间戳、BUILD-INFO、SHA256、tag |
| 文档与实现漂移 | 中 | 文档索引、单一事实源、闸门与版本检查 |

完整 findings 见 [审计报告](审计报告.md) 和 [Issues 整理](Issues整理.md)。
