## 3. 阅读路径

- **第一次使用**：README → 使用手册 → 程序接口（仅需要 CLI 时）。
- **部署到机群**：实施方案 → 使用手册 → 实施与验收记录。
- **修改代码**：开发手册 → 程序接口 → 编译环境 → 纪律与闸门。
- **审计/验收**：项目书 → 可行性分析 → 审计报告 → 实测证据 → 实施与验收记录。
- **发布新版本**：工程纪律 → 纪律与闸门 → 编译环境 → 实测证据 → 项目管理与排期。

## 4. 文档维护规则

1. **单一事实源**：API 字段只在 `程序接口.md` 定义；闸门只在 `纪律与闸门.md` 定义；排期只在 `项目管理与排期.md` 定义。其他文档用链接引用，不复制整表。
2. **状态诚实**：`PASS`、`PENDING`、`CANCELED`、`ACCEPTED` 必须和证据一致；未执行的测试不能写成通过。24 小时长稳测试已明确取消，不保留“待跑”暗示。
3. **版本冻结**：文档中引用二进制版本、tag、哈希时必须写明版本；不得把文档提交描述成已发布二进制的一部分。
4. **敏感信息**：文档、示例、截图、日志、Issue 中不得出现真实 SSH 密码、token、完整内网设备清单。示例统一使用 RFC 5737 文档地址。
5. **链接可验证**：新增或修改文档后运行链接检查；失效链接按缺陷处理。
6. **归一化**：术语统一使用“标准时间”“本机校时”“远程校时”“仅检测”“设备清单”；时间单位统一为 `ms`/`s`，存储和传输使用 UTC，展示使用北京时间。
