## 1. 目标与非目标

### 1.1 目标

1. 节点以 `server`、`client` 或 `auto` 模式运行。
2. `auto` 节点启动后发现集群；没有有效 server 时，eligible 节点参与选举。
3. 选举使用随机退避避免碰撞，最终用 `term + node_id` 确定性仲裁，避免脑裂/抖动。
4. server 先从外部 NTP 验证时间，再向 client 提供时间。
5. client 通过 NTP-like 四时间戳协议测量 offset/RTT，校验后按策略自动校时。
6. 提供集群状态 UI/API、日志、失败可见性。
7. 保持默认保守：自动写入必须显式开启；无有效时间源时不写。

### 1.2 非目标（1.1.0 首版）

- 不实现完整 NTPv4 服务器/协议兼容（首版为 ChronoSync 私有 NTP-like 协议）。
- 不做跨三层网段的自动发现；首版限定同一二层广播域。
- 不做 Byzantine 容错/多 server 投票；信任集群成员共享密钥。
- 不替代目标机现有 chrony/NTP；集群模式与系统 NTP 的冲突需运维选择。
- 不做 24 小时长稳测试（项目已取消）。
- 不修改 1.0.2 已发布二进制/Release。

## 2. 设计决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 发现 | UDP 广播/组播，高位端口 | 无中心、易部署；L2 限制明确 |
| 选举 | 随机退避 + 最高 term + 最低 node_id | 随机避免碰撞，确定性避免分裂 |
| 时间通道 | NTP-like UDP，四时间戳 + HMAC | 精度高于 HTTP，server 不必绑定 123 |
| 认证 | 集群共享密钥 HMAC-SHA256 | 防冒充/重放；不承诺机器可信 |
| 默认模式 | 生产建议手动 server；auto 显式开启 | 自动选举有网络/安全前提 |
| 自动写入 | 默认关闭；显式 `auto_apply` | 防止误写时钟 |
| 时间端口 | 默认 `18687/udp` | 避免与系统 NTP 的 123 冲突 |
| 发现端口 | 默认 `18686/udp` | 与时间面分离 |
| 配置 | 文件 + CLI 覆盖；密钥独立 root-only 文件 | 避免密钥进命令行/日志 |
| 版本 | 1.1.0 | 新数据面/端口/配置/安全评审 |

## 3. 术语与角色

| 术语 | 定义 |
| --- | --- |
| cluster | 同一 `cluster_id`、同一共享密钥的节点集合 |
| node_id | 128-bit 持久节点标识，首次启动生成并保存 |
| term | 选举任期，单调递增；用于冲突仲裁 |
| eligible | 允许成为 server 的节点（有外部 NTP、资源/权限满足） |
| server | 当前时间服务提供者，持有租约并发送心跳 |
| client | 从 server 取时并按策略写入本机 |
| candidate | 正在参与选举的 eligible 节点 |
| degraded | server 存在但外部 NTP 未验证/过期，不提供可信时间 |
| lease | server 通过心跳维持的软租约；超时触发重选 |

## 5. 配置设计

建议配置文件 `/etc/chronosync/cluster.toml`（Windows 为程序目录 `cluster.toml`），密钥独立 `/etc/chronosync/cluster.key`（0600）。

```toml
[cluster]
enabled = true
cluster_id = "chronosync-lab"
node_id = "persisted-uuid"          # 首次运行生成
mode = "auto"                       # server | client | auto
server_eligible = true
secret_file = "/etc/chronosync/cluster.key"

[discovery]
port = 18686
multicast = "239.255.42.99"
interval_ms = 1000
server_timeout_ms = 3500
seed_peers = []                     # 跨广播域/过滤时的静态入口

[election]
silent_window_ms = 2500
random_backoff_max_ms = 2000
claim_collect_ms = 500
lease_ms = 5000

[time]
port = 18687
samples = 5
interval_s = 60
max_offset_ms = 100
auto_apply = false
allow_large_step = false
```

校验规则：

- `cluster_id` 1–64 字符；`node_id` 固定长度/字符集。
- `mode=server` 时 `server_eligible` 必须 true；`mode=client` 不参与选举。
- 密钥文件必须存在、权限不超过 0600，禁止通过 CLI 传明文。
- 端口不能与自身监听冲突；发现/时间端口可配置。
- `samples` 3–9；`interval_s` 10–3600；阈值必须 >0。
- seed 地址只允许 IP/DNS，不含凭据。

## 6. 发现协议

### 6.1 传输

- UDP，默认 `18686`。
- 广播地址 `255.255.255.255` 或组播 `239.255.42.99`；首版二选一可配置。
- 消息为 UTF-8 JSON，单包 ≤1024 字节；HMAC 覆盖除 `mac` 外的规范化字段。
- 发送间隔 1s；接收端维护 peer 表，3.5s 无心跳视为失联。
- 频率限制：每源每秒最多 20 包；超限丢弃并计数。

### 6.2 消息类型

| 类型 | 发送者 | 作用 |
| --- | --- | --- |
| `HELLO` | 所有节点启动 | 声明存在、角色、term、能力 |
| `HEARTBEAT` | server | 续租、广播时间质量 |
| `CLAIM` | candidate | 宣布参选 term |
| `RESIGN` | server | 主动降级/退出 |
| `PEER_QUERY` | 新节点 | 请求当前 server/peer 状态（可选） |

### 6.3 字段

```json
{
  "v": 1,
  "type": "HEARTBEAT",
  "cluster_id": "chronosync-lab",
  "node_id": "5f2c...",
  "role": "server",
  "term": 7,
  "eligible": true,
  "ntp_verified": true,
  "server_epoch_ms": 1793789248123,
  "stratum": 2,
  "seq": 1234,
  "sent_at_ms": 1793789248200,
  "nonce": "base64url",
  "mac": "base64url"
}
```

- `seq` 单调递增，防重放；接收端按 node 维护窗口。
- `mac` = HMAC-SHA256(cluster_secret, canonical_json_without_mac)。
- `term` 只在选举/降级时递增，不随时钟变化。
- 收到 `cluster_id`/MAC 不符直接丢弃并计数，不回错误（防放大）。

## 7. 选举状态机

### 7.1 状态

`Boot → Discover → Client | Candidate → Server → SteppingDown → Client/Discover`

| 状态 | 行为 |
| --- | --- |
| Boot | 加载配置/密钥/node_id；校验端口 |
| Discover | 监听 2.5s；若有有效 HEARTBEAT → Client |
| Candidate | 仅 eligible；随机退避；发 CLAIM；收集 500ms |
| Server | 持有租约；发 HEARTBEAT；提供时间（仅 verified） |
| SteppingDown | 收到更高 term/同 term 更小 node_id；发 RESIGN，转 Client |
| Client | 跟随 server；超时回 Discover/Candidate |
| Degraded | server 时间不可信，停止时间响应；client 进入锁定 |

### 7.2 选举算法

```text
on no valid server:
  if !eligible: stay Client/Fault
  wait silent_window (2.5s)
  delay = random(0, 2000ms)       # 只用于错峰
  send CLAIM(term = last_term + 1)
  collect claims for 500ms
  candidates = highest term
  winner = min(node_id) among candidates
  if winner == self: become Server(term, lease=5s)
  else: become Client(winner), remember term
```

- 同一 term 多 claim：最低 node_id 胜；其他节点必须接受，避免各自为政。
- server 每 1s HEARTBEAT；client 3.5s 未收到 → 重新发现。
- server 看到更高 term 或同 term 更小 node_id → SteppingDown。
- 分区时两个 server 可能同时存在；合并后按 term/node_id 收敛。首版不承诺分区期间全局唯一。
- 不进行周期性随机重选；server 稳定运行，避免时间源抖动。

### 7.3 防抖动

- server 最短任期 10s，除非故障/显式降级。
- 选举失败后退避 2–5s，避免广播风暴。
- 角色变化写日志/指标；10 分钟内角色切换次数纳入验收。

## 8. 时间服务协议

### 8.1 包格式

建议 64 字节固定头 + 32 字节 HMAC：

| 偏移 | 字段 |
| --- | --- |
| 0–3 | magic `CSNP` / version |
| 4 | type (request/response) |
| 5 | flags |
| 6–7 | reserved |
| 8–15 | seq (u64) |
| 16–23 | t1 client transmit (NTP 64-bit) |
| 24–31 | t2 server receive |
| 32–39 | t3 server transmit |
| 40–47 | server_epoch_ms (u64) |
| 48–55 | nonce (u64) |
| 56–59 | stratum/quality/ref_age_s |
| 60–63 | reserved |
| 64–95 | HMAC-SHA256 |

- 请求携带 t1/nonce；响应填 t2/t3/质量并签名。
- client 收到后计算 `offset=((t2-t1)+(t3-t4))/2`、`rtt=(t4-t1)-(t3-t2)`。
- 响应必须满足：MAC 正确、seq/nonce 匹配、`ntp_verified=true`、参考年龄 ≤300s、server term 未过期。
- 时间戳使用 NTP 64-bit，避免毫秒精度损失；内部仍可转 epoch ms。

### 8.2 Server 质量

- 只有外部 NTP 已验证且参考年龄 ≤300s 才响应。
- 外部 NTP 失效：进入 Degraded，停止响应；client 锁定并告警。
- 不声称 stratum 1；使用保守 stratum（如 2/3）和 `source_quality`。
- server 自身时钟被其他服务改动时，重新验证后再服务；记录 generation。

### 8.3 Client 应用策略

1. 连续 5 次采样，剔除 RTT > 3×中位数的样本。
2. offset 取中位数；RTT 取最小值对应样本或中位数。
3. `auto_apply=false`：只记录/展示，不写时钟。
4. `auto_apply=true`：偏差 > `max_offset_ms` 且连续 2 轮稳定才写入。
5. 偏差 > `allow_large_step` 阈值（默认 5s）时默认拒绝，需显式允许。
6. 写入需要 root/管理员；无权限只告警。
7. 写入后复读校验；失败/偏差过大记录错误，不重试风暴。
8. 与系统 NTP 冲突：集群模式文档要求关闭/让行目标 NTP；工具不自动改目标 NTP 配置。

## 9. 关键时序

### 9.1 首次启动（全 client）

```text
A/B/C 启动 → Discover 2.5s → 无 server
→ eligible 各自随机退避 → CLAIM(term=1)
→ 收到 claims → min(node_id) 胜出（假设 B）
→ B: Server, 外部 NTP 验证 → HEARTBEAT + 时间服务
→ A/C: Client → 采样 B → 校验 → 可选写入
```

### 9.2 Server 故障

```text
B 停止心跳 → A/C 3.5s 超时 → Discover
→ eligible 重新 CLAIM(term+1) → 胜者 C
→ C 外部 NTP 验证 → 服务；A 跟随 C
```

### 9.3 旧 server 恢复

```text
B 恢复，term 较低 → 收到 C HEARTBEAT(term 更高)
→ B SteppingDown/RESIGN → Client
```

### 9.4 脑裂合并

```text
分区两侧各自 server → 合并后收到更高 term/更小 node_id
→ loser RESIGN → client；双方按 term 收敛
```

## 11. 安全与威胁模型

| 威胁 | 控制 | 残余风险 |
| --- | --- | --- |
| 冒充 server | 共享密钥 HMAC、cluster_id、nonce/seq | 密钥泄露即可冒充 |
| 重放旧时间 | seq/nonce、term、质量年龄 | 窗口内重放 |
| 恶意成员下发错误时间 | server 必须外部 NTP verified；client 校验 | 有密钥的恶意成员仍可撒谎 |
| 广播风暴/DoS | 速率限制、包大小、peer 上限 | 内网 DoS |
| 密钥泄露 | 0600 文件、不进日志/CLI、轮换流程 | 主机被攻陷 |
| 自动写时钟误伤 | 默认关闭、阈值/滞回、大步长拒绝、dry-run | 业务时间跳变 |
| 未授权节点加入 | 密钥/网络隔离；可选 allowlist | 同密钥即可加入 |

首版不做 Byzantine 容错；信任边界是“持有集群密钥的可信节点 + 可信局域网”。若需要更高保证，后续增加多 server 投票/签名身份/证书。

## 12. 失败行为矩阵

| 场景 | server | client | 是否写入 |
| --- | --- | --- | --- |
| 无 server，有 eligible | 选举 | 等待 | 否 |
| 无 server，无 eligible | 无 | 锁定/告警 | 否 |
| server NTP 未验证 | Degraded，停止响应 | 拒绝 | 否 |
| server 崩溃 | 重选 | 等待新 server | 否 |
| 广播阻断 | 可能重复选举 | 用 seed/告警 | 依据认证/仲裁 |
| 两 server 脑裂 | 高 term/低 node_id 胜 | 选一个 | 可能短暂不一致 |
| client 无 root | — | 只报告 | 否 |
| 时钟大步长 | — | 默认拒绝 | 否 |
| MAC/seq 错误 | 丢弃/计数 | 丢弃/告警 | 否 |

  - `server_age_ms`、`ntp_ref_age_ms`
  - `sync_offset_ms`、`sync_rtt_ms`、`sync_failures`
  - `peer_count`、`packet_drops`
- 日志不得含密钥/MAC 原文/密码；node_id 可截断展示。

## 14. 安装与部署变更

- `install.sh` 新增 `--mode server|client|auto`、`--cluster-id`、`--cluster-secret-file`、`--discovery-port`、`--time-port`。
- 生成 `cluster.toml` 和 0600 密钥；不把密钥写入服务参数。
- 防火墙：放行 UDP 发现/时间端口，仅限集群网段。
- Windows：启动脚本/服务使用配置文件；client 写时钟需管理员。
- AudioSys/Buildroot：持久目录保存配置/密钥；开机恢复。
- 升级：1.0.2 → 1.1.0 保留旧 CLI 兼容；集群默认关闭，避免行为突变。

## 15. 测试策略

### 15.1 单元

- 配置校验/密钥权限。
- 消息规范化/HMAC/seq/nonce/重放。
- 选举：同 term 多 claim、term 升级、随机退避边界、降级。
- 时间包编码/解码、offset/RTT、质量拒绝。
- 应用策略：阈值/滞回/大步长/无权限。
- 状态机非法转换。

### 15.2 仿真

- 5/7 节点虚拟时钟/虚拟网络；丢包 0/10/30%、延迟、重排。
- 分区、合并、server 崩溃/恢复、旧 server 回归。
- 恶意 MAC/重放/错误 term/伪造 server。
- 选举时间、角色切换次数、无写入断言。

### 15.3 集成/真机

- 5 台 Linux + 1 Windows + 1 ARM64；同 L2。
- 全 client 选举、kill server、广播阻断、seed 回退。
- NTP 断开/恢复、client 无 root、系统 NTP 冲突。
- 只读优先；写入测试需授权测试机。
- 不执行 24h 长稳（项目已取消）；以 10 分钟角色稳定性 + 故障用例替代，不作为 24h 声明。

### 15.4 安全

- 无密钥/错密钥/重放/降级 term/畸形包/fuzz。
- 端口扫描/广播风暴限速。
- 密钥不出现在日志/进程参数/包。

## 18. 验收标准

1. 5 台全 `auto`：≤10s 选出唯一 server；无重复 server 心跳。
2. server 外部 NTP 未验证：client 0 写入，状态显示锁定。
3. 5 台 client：≤60s 完成首次同步；offset 目标 ≤100ms（按网络记录实际值）。
4. kill server：≤15s 完成重选；client 恢复；旧 server 回归降级。
5. 广播阻断/seed 模式：按文档行为工作或明确失败，不静默脑裂。
6. 错误 MAC/重放/降级 term/伪造 server：全部拒绝并计数。
7. `auto_apply=false`：全过程 0 写入；无 root：0 写入。
8. 10 分钟无角色抖动；角色切换次数≤2（故障注入除外）。
9. 六平台构建/启动；安装/防火墙/密钥权限正确。
10. G1–G13 全量通过；文档/API/升级说明一致。
11. 不把 24h 长稳列为验收项（已取消）。

## 19. 风险与应对

| 风险 | 概率/影响 | 应对 |
| --- | --- | --- |
| 广播被 Wi-Fi/交换机过滤 | 中/高 | seed、文档限制、集成测试 |
| 脑裂/角色抖动 | 中/高 | term/lease/最短任期/仿真 |
| 恶意 server/密钥泄露 | 中/高 | HMAC、密钥权限、网络隔离、轮换 |
| 自动写时钟误伤 | 中/高 | 默认关闭、阈值/滞回、大步长拒绝 |
| Windows 权限/服务差异 | 中/中 | 管理员检测、启动器、真机 |
| 与系统 NTP 冲突 | 中/中 | 文档要求让行；不自动改目标 NTP |
| 测试环境不足 | 中/高 | 早期锁定 5+ 节点/虚拟机；seed 仿真 |
| 跨三层需求 | 高/中 | 首版不支持；后续设计 relay/seed |
| 进度压缩 | 中/高 | 20% 缓冲；MVP 先手动 server |
