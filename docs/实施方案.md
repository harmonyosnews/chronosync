## 1. 总体架构

```text
                    NTP/SNTP (UDP 123)
  多源时间服务器 ───────────────┐
                                v
  ┌────────────────────── 控制机 ChronoSync ──────────────────────┐
  │  main.rs   CLI / 监听 / 端口回退 / 浏览器打开                  │
  │  app.rs    HTTP API / 状态机 / 并发控制 / 日志                 │
  │  ntp.rs    多源采样 / 中位数 / RTT 选择 / 标准时间锚点          │
  │  remote.rs SSH 连接 / 认证 / 预检 / 写入 / 结果标记             │
  │  scan.rs   网卡/网段规划 / TCP 22 / 邻居表 / 反向 DNS            │
  │  web/      单文件 WebUI（include_str! 嵌入）                    │
  └───────────────┬───────────────────────────────────────────────┘
                  │ SSH 22（密码或 keyboard-interactive）
                  v
  目标机：date -u -s @epoch → 可选 hwclock → 可选时区 → 读取校验
```

控制机是唯一需要访问 NTP 的节点；目标机只需被 SSH 访问。所有时间在内存和 API 中使用 UTC epoch 毫秒，展示层转换为北京时间（UTC+8）。

## 2. 组件与职责

| 组件 | 职责 | 关键限制 |
| --- | --- | --- |
| `main.rs` | 解析 CLI、认证头、监听端口、端口回退、重复实例探测、优雅退出 | 端口最多尝试 10 个后继；`--auto-port` 对任何绑定错误继续 |
| `app.rs` | API、设备校验、运行状态、并发、日志、日志落盘 | 最多 64 台；8 台并发；日志 8000 条；任务互斥 |
| `ntp.rs` | 并行查询、超时、离群过滤、单调时钟锚点 | 1.5s/源；至少 1 个源成功；不认证 |
| `remote.rs` | SSH 连接/认证/执行、命令生成、结果解析 | 连接 10s、认证 12s、执行 25s；输出截断 |
| `local.rs` | 本机时间、权限、时区、RTC | Linux `clock_settime`；Windows `SetSystemTime` |
| `scan.rs` | 网段规划、TCP 探测、邻居表、反向 DNS | 4 网段/1024 地址；`/22` 最小；128 探测并发 |
| `web/index.html` | 中文 UI、状态轮询、日志、确认弹窗 | 无外部资源；CSP 允许内联脚本/样式 |
| `install.sh` | 安装、服务注册、AudioSys 持久化、卸载 | 安装需要 root；不修改目标设备 |
| `build.rs` | 注入 target/variant/time | 构建元数据只读 |

## 3. 关键流程

### 3.1 启动

1. 解析 CLI 和 `CHRONOSYNC_AUTH`，校验 NTP 源非空。
2. 初始化本地环境（主机名、权限、时区）和日志目录。
3. 首次 NTP 探测：成功则建立已验证参考；失败则建立“未验证”系统时钟参考，但默认锁定校时。
4. 绑定端口；重复实例探测 `/api/health`；`--auto-port` 时按顺序尝试后继端口。
5. 启动 axum，输出访问地址/安全提示；可选打开浏览器。
6. 收到 Ctrl+C/SIGTERM 时优雅关闭。

### 3.2 远程校时

```text
校验请求 → 获取运行锁 → 刷新 NTP（或 5 分钟内快照）
        → 8 并发连接目标 → 预检（hostname/epoch/tz）
        → dry_run? 返回 checked
        → 写入 epoch → 可选 RTC/时区 → 读取校验
        → 记录状态/偏差/警告 → 汇总 → 保存日志
```

- 预检失败不写入。
- NTP 失败且无有效快照时不写入。
- 写入后校验偏差超过 2500 ms 标为失败，提示可能有其他校时服务。
- 可选步骤失败只产生警告，不否定系统时间写入。

### 3.3 本机校时

先检查权限；检测模式只读。写入后读取本机时间校验，偏差超过 1500 ms 标失败。Windows 跳过 RTC 独立写入和时区修改。

### 3.4 扫描

1. 空范围：读取非虚拟 IPv4 接口，每个接口最多取 /24，跳过自身地址。
2. 自定义：解析逗号/空白分隔 CIDR，拒绝 /22 以上大网段，去重，最多 1024 地址。
3. 128 并发 TCP 22 探测：连接成功=SSH；连接拒绝=活跃但无 SSH；超时/不可达=不活跃。
4. Unix 读取 `ip neigh`，补充 ARP 邻居。
5. 32 并发反向 DNS；返回活跃、SSH 数、主机列表。

### 3.5 日志

- 运行日志按任务写入；下载接口导出当前进程日志。
- 所有日志进入前做控制字符/ANSI 清理和长度截断。
- 设备标签只保留名称和地址；密码不进入日志。
- 日志目录创建/写入失败只警告，不终止校时。

## 4. 部署模式

| 平台 | 识别 | 安装位置/服务 | 注意 |
| --- | --- | --- | --- |
| systemd | `/run/systemd/system` + systemctl | `/etc/systemd/system/chronosync.service` | 默认 root，支持本机校时 |
| OpenRC | rc-update + rc-service | `/etc/init.d/chronosync` | GentooPlayer 常用 |
| procd | `/sbin/procd` + `/etc/rc.common` | `/etc/init.d/chronosync` | iStoreOS/OpenWrt |
| AudioSys/Buildroot | `/audiosys` + `/dpdk/diretta.sh` | `/opt/chronosync` + `/audiosys/chronosync` + CONFIG 钩子 | `/opt` 可能内存盘，需持久化 |
| BusyBox/SysV | `/etc/init.d` | `/etc/init.d/S99chronosync` | 根文件系统可能不持久 |
| Windows | zip + bat | 同目录 `chronosync.exe` | `--open --auto-port` |

安装：

```bash
sudo ./install.sh --auth admin:'强密码' --bind 0.0.0.0 --port 8686
```

先看计划：

```bash
./install.sh --dry-run
```

## 5. 配置

| 配置 | 来源 | 默认 | 说明 |
| --- | --- | --- | --- |
| 监听地址 | `--bind` | `0.0.0.0` | 建议 `127.0.0.1` 或可信网卡 |
| 端口 | `--port` | `8686` | 0 不允许；自动回退最多 +10 |
| NTP 源 | `--ntp-servers` | 阿里云/Cloudflare/pool | 逗号分隔，去重 |
| 认证 | `--auth` / `CHRONOSYNC_AUTH` | 无 | Basic，密码不进进程参数 |
| 日志目录 | `--log-dir` | `./logs` | 安装器改为 `/var/log/chronosync` |
| 系统时钟降级 | `--allow-system-clock` | 关闭 | 危险，仅显式授权 |
| 自动打开 | `--open` | 关闭 | Windows 启动器启用 |
| 自动端口 | `--auto-port` | 关闭 | Windows 启动器启用 |

## 6. 上线步骤

1. **准备**：确认控制机网络、NTP、目标 SSH、维护窗口；准备受控凭据，不写入仓库。
2. **只读验收**：启动控制台 → 添加少量设备 → “仅检测” → 核对主机名/时区/偏差 → 扫描验证。
3. **小批量写入**：选 1 台非关键设备，关闭仅检测，确认写入和校验；检查 RTC 警告。
4. **扩大**：按批次增加；失败设备先排查，不盲目重试。
5. **记录**：保存日志、版本、构建时间、目标数量和异常分类。

## 7. 回滚

- **控制台回滚**：停止服务 → 用上一版本二进制替换 → 重启；不触碰目标时钟。
- **配置回滚**：恢复 `/opt/chronosync/install.conf`、`auth`、服务文件；卸载用 `install.sh uninstall`（默认保留日志）。
- **目标时间回滚**：本工具不保存目标原时间；如写入错误，需用可信时间源重新校准并检查目标 NTP 服务。上线前必须先只读验证。
- **端口冲突**：停止占用进程或改端口；不要盲目杀未知 PID。

## 8. 故障处理矩阵

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 校时已锁定 | NTP 全部失败 | 检查 UDP 123/源地址；修复后刷新源 |
| 目标不可达 | 路由/防火墙/SSH 端口 | 先手工 SSH；检查网段 |
| 认证失败 | 密码/用户/只允许 keyboard-interactive | 确认账号；工具已自动回退 |
| `hwclock` 失败 | 无 RTC/驱动缺失/权限 | 检查 `/dev/rtc*`；x86 可 direct ISA；否则跳过 |
| 写入后校验失败 | 其他 NTP 服务/只读时钟 | 查目标时间服务；不要重复盲写 |
| Windows 端口错误 | 10048/10013/CLOSE_WAIT | 自动换端口；按 PID 排查 |
| 日志目录不可写 | 权限/只读 FS | 改 `--log-dir` 或修复权限 |

## 9. 安全控制

- 默认不保存密码；记住密码必须显式开启。
- 日志脱敏、无密码。
- CSP、`X-Content-Type-Options`、`X-Frame-Options: DENY`、`Referrer-Policy`。
- Basic 认证不是 TLS；生产必须网络隔离或反向代理 TLS。
- SSH 主机密钥当前不固定；高风险环境需后续版本支持 pinning。
- 不在目标机安装服务、不修改目标 NTP 配置。
